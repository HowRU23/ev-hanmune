# Workflow: 새 도구 추가하기

## 목표
"전기차 한눈에" 사이트에 새 도구(계산기, 판정기, 외부 서비스 링크아웃 등)를 추가한다.

## 도구와 가이드(글)의 차이
가이드(`workflows/add-guide.md`)는 "정보를 설명하는 글"이고, 도구는 "바로 쓰는 기능"이다. 보조금 조회, 유지비 계산기처럼 사장이 "페이지" 말고 "기능"으로 취급하고 싶다고 한 주제는 `content/guides/`가 아니라 여기로 간다.

**도구는 하나로 묶는 인덱스 페이지 없이, 각각 헤더 네비게이션에 직접 노출한다** (2026-09-15 결정: 처음엔 `/tools` 인덱스로 묶었다가, 사장이 "홈/가이드 옆에 각각 따로 빼두라"고 해서 변경). 예: "보조금 찾기", "유지비 계산기"가 각각 독립된 메뉴 항목.

기존 예시: `/tools/ev-subsidy` (사장이 직접 만든 토스 미니앱 "전기차 보조금 찾기"로 링크아웃), `/tools/cost-calculator` (유지비 계산기).

## 구조
- 도구 상세 페이지: `src/app/tools/{slug}/page.tsx`를 직접 작성 (가이드처럼 마크다운 자동 렌더링이 아니라, 도구마다 UI가 다르므로 페이지를 직접 만든다)
- 새 도구를 추가하면 `src/components/Header.tsx`의 nav에 직접 `<Link>`를 추가한다
- 외부 앱/서비스로 링크아웃하는 도구는 버튼 + QR코드(`src/components/QrCode.tsx` 재사용) + 안내 문구를 같이 보여준다. PC 접속자도 고려해서 QR과 안내 문구를 조건 없이 항상 같이 띄운다 (링크가 모바일 전용 앱으로 연결되는 경우).
- 계산기류는 사용자가 직접 입력하는 값과 기본값(가정치)을 명확히 구분한다. **기본값은 출처를 확인할 수 있는 것만 넣는다.** 출처를 못 찾은 항목(예: 아파트 자체계량 충전단가)은 어설픈 추정치를 기본값으로 밀어넣지 말고, 사용자가 직접 입력하게 비워둔다.

## 검토 프로세스
가이드와 동일하게, 새 도구도 바로 코드로 만들지 않고 먼저 Notion 검토 DB([전기차 한눈에 콘텐츠 검토](https://app.notion.com/p/b27d360f0bdc43a1b72dd9669f98c1d2))에 초안을 올려 사장 검토를 받는다. 다만 도구는 "주장하는 사실"이 거의 없는 경우(순수 계산 로직, 링크아웃)가 많아서, 사장이 대화 중에 이미 구체적인 사양(문구, UX, 링크)을 직접 확정해준 경우에는 그 자리에서 바로 구현해도 된다. 애매하면 먼저 물어본다.

## 글쓰기 스타일 규칙
`workflows/add-guide.md`와 동일. em dash(—) 금지, **리스크 문구 배제 규칙**(확실하지 않은 규칙성/예외 있을 수 있는 단정 문장은 아예 안 쓴다) 그대로 적용. "왜 안 되는지/왜 여기서 직접 안 하는지" 같은 변명 톤도 쓰지 않는다. 2026-09-15 사장 피드백: 가치만 말하고 이유는 설명하지 않는다.

## 단계
1. Notion에 도구 초안 페이지 생성 (필요 시). 슬러그/설명/링크/출처를 정리.
2. 사장 검토 또는 대화 중 확정.
3. `src/app/tools/{slug}/page.tsx` 작성.
4. `src/components/Header.tsx` nav에 링크 추가.
5. `npm run build`로 확인.
